## 四分支必须冻结实际策略

当前 `StrategyStore._experiment()` 每个 scope 生成随机 salt，并默认将用户分成 50/50 的 `rules-v1` /
`content-v1`。scope 和用户 ID 本就不同，因此只贴 `fixed / recommendation / ads / joint` 标签会得到
四份混合策略，不能证明纯策略对照。`content` 也不天然等于 live 语义重排：没有实际 rerank callback 时
回执是 `content_rule` 或降级，需按真实 `ranking_mode` 分开报告。

最小复用方式：保留现有两组及稳定分桶，初始化时将同一分支的 control/treatment 指向同一冻结版本。
随后获准改变推荐的分支也必须两组同步指向同一新版本；若现有一次动作只支持单组，要补一份原子、
受 grant/CAS 约束的双组切换语义，或明确将对照定义为共同的固定分桶干预，并保持各分支逻辑用户分桶一致。
不能临时直接改 assignment、绕过授权写策略，或在看到成绩后挑选分桶。

| 分支 | 推荐配置 | 投放配置/后续动作 | 结果解释 |
|---|---|---|---|
| 固定规则 | 两组同一固定 rule 版本 | 初始相同广告；后续无优化写，仍有统一预算/售罄安全保护 | 确定性基线；安全暂停不算经营优化 |
| 仅改推荐 | 可在约束内修改并记录实际新版本 | 广告预算/素材保持初始策略；仅统一安全保护 | 效果来自推荐策略干预范围 |
| 仅改投放 | 两组同一固定 rule 版本 | 可在 grant 内预算/素材/启停 | 效果来自投放干预范围 |
| 联合调整 | 可按冻结协议修改推荐版本 | 可在 grant 内预算/素材/启停 | 联合干预；不预设一定优于单独干预 |

各分支初始逻辑商品、价格、库存、用户偏好、广告预算和机会表同构，真实 ID 各自独立。
默认量级约 20 商品/40 SKU/100 用户/6 活动/12 素材；如缩小需在运行前注明规模和限制，不能代替覆盖门禁。
至少三个种子在运行前冻结（可用 17/42/73，选定后不能按成绩替换），每个都有完整四分支。
随机数以固定算法从 `(seed, opportunity_id, draw_kind)` 派生，不含 branch/run/真实 SKU ID；
分支多一次模型/工具调用不能移动后续抽样。隐藏概率只在模拟器，Agent 看不到，也不能给“优化”分支硬加收益。

每轮先登记机会、输入和已安排未来事件，再通过本项目 API 执行行为；等待预期 Java 订单/付款/退款和
Growth APPLIED 事件/归因投影达到可核对水位。空队列或固定 sleep 不证明本轮事实齐全。
显式安排的延迟付款记录为未来事件，不无限阻塞本轮，后续通过原订单和原归因回收。
7 天/24 小时精确边界沿用固定时间合同测试，并标记非真实运行七天的在线实验。

至少两次 live 重复须使用相同冻结模型请求版本、prompt/Skill/index/算法/策略/数据版本和外生输入，
每次用新独立资源；记录供应商实际 returned model，未返回快照就是 unknown/null。
不同 prompt 的 F5 开发重跑不能计入这两次。报告每种子/分支/重复的付款、退款、净额、广告费、
净额减广告费及相对基线配对差；列范围/波动和样本数，避免将小模拟样本宣称为显著真实增收。

## RAG 冻结及评分

现有 `smartlect-rag-v1` 为 44 条已标注合同：32 development、12 holdout；manifest 自称 `not_run`，
只证明事先有预期，不是检索/回答成绩。F4/F5 禁止打开全量 JSONL。正式 F6 可先由 runner 选择开发集，
模型只收到用户原话和合规检索内容，不收到答案标签/禁止项/注入 canary 预期。

留出读取前保存模型请求配置、prompt/Skill/索引/算法/策略/数据 SHA 的冻结产物。冻结后才执行 12 条，
两次真实调用都保留原输出与失败；开发/留出分别报告，不能混算或按成绩删除问题。
如果根据留出修改实现，该批结果必须标明已污染，不可沿用“未调试留出”主张。
已有状态披露通用 secret 扫描曾机械读取 RAG 字节、题答未进入模型/调试；继续保留该说明，不能写“文件从未读取”。

复用 manifest 的完整 runtime_setup_contract：每病例/重复独立 scope，真实用户会话；固定知识通过受保护 API
创建、索引、发布/过期/撤回，验证状态后再问。多轮前文必须来自实际模型答复，不能填标准答案。
setup 失败单列，不能当作拒答正确。保留候选/重排/最终可见块、原始回答、引用 doc/version/偏移/行号和 trace。

评分执行 manifest：Recall@4/@8 的分母排除无合规相关文档的病例；引用必须逐项支持事实，不能仅验文档 ID 存在。
事实完整性与禁说项按原文及真实回执核对，不能仅用字符串包含或 LLM 自评分。
拒答/转人工须无无依据断言，需要人工时有持久工单；ACL/撤回/过期/注入项核对候选、模型上下文和新引用。
原有历史引用的保留只适用于对应合同允许的历史展示，不能再次当作当前有效证据。

## 经营、可靠性与性能的补证

经营五类分别保留：库存为 0 的事实和售罄暂停；成熟低 CTR 的同活动曝光/点击双证据及素材试验；
Java PAYMENT_ATTEMPT DECLINED 的非财务事实；已确认退款及净额回冲；未成熟/未知观测的保留判断。
每类需要正确证据引用、有限计划或无动作、grant/CAS 结果、回执和新的外生观测。
单测中的五类 typed metric 不能代替 live 诊断；F5 的 250 曝光/1 点击纵切是功能练习，不是收益评测。

可靠性复用现有 MySQL/HTTP/AMQP 路径，并在当前版本执行：付款/退款明细总和与 Java/账本/归因三个视图一致，
广告/推荐转化维度不能相加变成两份收入；消费者提交未 ACK 后重投不改原 raw_json/fingerprint。
进程重启后恢复原提案/动作键，并发点击/预算、过期/撤销 grant、CAS 冲突和部分执行逐项保留结果。
历史事件/其他已注册 scope 在新测试和 reset 前后比较指纹，禁止测试清库隐藏重复或错误。

Provider 已有每个 attempt 的 `latency_ms/first_delta_ms/usage/cost_estimate_cny` 和运行耗时，直接复用统计。
分别汇总模型 attempt、系统任务和端到端体验；声明 P50/P95 算法及样本数。
首字测用户端真正可见的正文，不用进度事件、首 HTTP 字节或原始模型 JSON 时间替代；Merchant 无 token 流时
首个完整可见结果单列，不捏造流式首字。人工确认等待与系统执行分开计时。失败/未知 token 保留 null，
费用只能按记录的价格版本估算，不能写为真实账单或未测 SLA。

## reset-demo 和 F7 的退出条件

`reset-demo --run-id` 只能接受 Java registry 中本项目已注册运行，列举并验证其 manifest 资源和状态。
操作先停止该 scope 的新流量、Agent/确认写入并解决在途回执，等已计划业务/Outbox/消费投影到达水位，
然后经 Java 权威重置接口处理该运行拥有的交易/库存/会话；Growth 只处理自身表。
必须定义旧消息如何被隔离或被永久退役 scope 拒绝，证明重置后旧消息重投不会复活数据或污染新运行。
具体退役/重建策略按现有 registry 最小实现选择；不能直接 Python 改交易表、全局 FLUSHALL、删除 Docker 卷，
