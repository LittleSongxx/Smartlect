# 线上客服答不出店规问题：四个问题叠加的检索失效

日期：2026-10-08 起排查、2026-10-10 定位并修复 ｜ 状态：功能已恢复（10-08 记录的登录交互问题同日）
前次记录：[未登录与访客凭证失效的交互修复](../2026-10-08/未登录与访客凭证失效的交互修复.md)

## 现象

线上问客服"退换货政策"，回答是「本轮没有当前有效资料，无法依据已发布政策作答…可以选择人工客服」。
这类店规问题本该有**带引用的准确回答**（本地就是），不该落到"没有资料"。

## 排查链：四件事依次挡住

### 1（最直接）线上 venv 缺 `aiohttp`——ES 客户端初始化就失败，检索被静默跳过

assistant 启动日志里反复出现：

```
File ".../elastic_transport/_node/_http_aiohttp.py", line 81, in __init__
ValueError: You must have 'aiohttp' installed to use AiohttpHttpNode
```

`AsyncElasticsearch` 走 `elastic_transport` 的 aiohttp 节点，`aiohttp` 缺失就在构造时抛错；
`ensure_schema()` 吞掉异常继续启动，于是 `es_client()` 恒为 `None` ——
**所有 ES 检索被静默跳过**，知识自然永远命中不了。

依赖声明里只有 `elasticsearch==8.19.0`，没有 `aiohttp`（async extra 不会自动带上）。
线上是通过 `pip install --no-deps ./assistant` 部署的，也不会补这一层，所以线上一直没有。
本地同样没装，但本地走的是"ES 不可用 → 内存 BM25"降级路径，恰好能答出来——**两边现象不同，掩盖了问题**。

### 2 ES 索引里根本没有知识——BM25-only 发布不写 ES

线上 MySQL 侧数据完好：`knowledge_catalog` 1 条、`knowledge_document` **32 篇全部 PUBLISHED**、
`knowledge_chunk` 32 条；但 ES 里只有 `smartlect-products`，**没有 `smartlect-knowledge`**，
Qdrant 的 collections 列表也是空的。`knowledge_index_job` / `knowledge_index_attempt` 两张表**都是 0 条**。

读代码定位到写 ES 的位置——`knowledge.py` 的 `_mirror_vector`：

```python
"""索引双写：Qdrant 向量 + ES BM25 文档……"""
results.append(await hybrid_search.upsert_vectors(...))
for chunk_id, vector in mapped.items():          # ← 遍历的是向量
    results.append(await hybrid_search.index_chunk(...))   # ES 写入在这里面
```

**ES 的写入被嵌在「遍历向量」的循环里**，只有走过 embedding 的发布才会执行。
线上没有 `SMARTLECT_EMBEDDING_API_KEY`，`embedding_enabled()` 为假，发布走 `record_sync_publish`
——那个分支的注释写着 "BM25-only publish still leaves an ops-visible DONE job"，但它**只写了一条任务记录，
没有真的写 ES**。于是「BM25-only」这条设计路径实际是空操作，ES 永远为空。

### 3 线上 ES 没有 smartcn 插件，索引创建会 400

`ensure_schema()` 建索引时写死 `"analyzer": {"default": {"type": "smartcn"}}`，
而线上 ES 未按 compose 注释「需 build Dockerfile」构建插件，实测：

```
illegal_argument_exception: Unknown analyzer type [smartcn] for [default]
```

索引创建失败后由 dynamic mapping 兜底，中文按 standard 切分，检索质量差。

### 4 补数据时的编码坑

首次用 `mysql -N -B` 导出 JSON 聚合，中文全部变成 `?`（客户端字符集不是 utf8mb4），
写进 ES 的是乱码，检索命中 0。加 `--default-character-set=utf8mb4` 后正常。

## 处置

1. **线上安装 `aiohttp`**（3.14.4）并重启 assistant —— ES 客户端恢复可用
2. **补建 ES 索引**：新建脚本 `/tmp/reindex2.py`（服务器侧），从 MySQL 读 32 篇已发布切片写入
   `smartlect-knowledge`，显式 mapping + **ES 内置 cjk 分析器**（bigram 切分中文，无需插件），
   文档 ID 沿用 `{scope}:{doc_id}:{version}:{chunk_id}`，可幂等重跑
3. **声明依赖**（`assistant/pyproject.toml`）：`elasticsearch[async]==8.19.0` + `aiohttp>=3.9`，
   并注明缺它会静默跳过 ES 检索；本地环境同步补装，避免两边行为不一致

## 验证

**检索层**（ES 直查，与线上服务同口径的 BM25 查询）：

| 查询 | 命中 | Top 文档 |
|---|---|---|

**端到端**（线上真实问答，Chromium）：问"退换货政策"得到**带引用 [1][2] 的完整回答**
—— 退货条件、换货规则、退款说明三段俱全，引用挂到「换货与更换规格」「退货条件与期限」两篇文档；
不再是"没有资料"或转人工。

## 未完成项（真正的根治还没做）

- **代码层根因未修**：`_mirror_vector` 把 ES 写入嵌在向量循环里，且 `record_sync_publish` 不写 ES。
  本次是用脚本**补建**了存量索引，**新发布的文档在无 embedding 的部署上仍不会进 ES**。
  正确改法：让 BM25-only 路径也调用 `index_chunk`（不传 index_version），并加一条"重建 BM25 索引"的入口供存量环境使用。
- **`ensure_schema()` 吞异常**：ES/客户端初始化失败只留下栈，不影响启动也不告警，
  这正是问题能潜伏这么久的原因。至少应打一条明确 WARN 或计入健康度。
- **分析器不一致**：代码用 `smartcn`（插件缺失即 400），线上实际是本次手工建的 `cjk`。
  代码里应改为"优先 smartcn、缺失回退 cjk/standard"的探测式创建，否则代码路径重建索引会失败。
- **Qdrant 仍为空**（无 embedding），当前检索是纯 BM25；要提升"准确回答"的质量需要配置
  `SMARTLECT_EMBEDDING_API_KEY` 走向量混检。
- 线上 ES 无中文插件这一点也不只影响知识：`smartlect-products` 同样是 dynamic mapping。
