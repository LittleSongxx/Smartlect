# 拆分订单事务边界：Feign 移出事务（补足欠设计）

日期：2026-10-07 ｜ 状态：已完成，全仓 BUILD SUCCESS

## 需求

`postOrder` 与 `createConfirmed` 上的 `@Transactional` 将 6 次 Feign 远程调用全部包在订单库事务内——连接被占秒级（压测实测 18.1s），高并发抽干连接池；且进程在订单 insert 后、库存扣减前崩溃会产生幻影库存。

## 方案：五阶段拆分

```
Phase 1（无事务）:     prepareOrder — 只读 Feign（地址/快照/库存预检），不占连接
Phase 2（远程服务事务）: lockCoupon + deductStock — 远端自己的事务
Phase 3（短本地事务）:  transactionTemplate.executeWithoutResult — 仅 4 个 mapper insert + Outbox
Phase 4（事务外）:     支付意图 + 支付链接 + 超时消息注册
Phase 5（catch 补偿）:  库存回补 + 券解锁 + 远程补偿台账
```

## 具体变更

### OrderInfoServiceImpl

1. `postOrder` / `createConfirmed` 移除 `@Transactional`
2. `createOrder` 拆为五阶段（如上），Phase 3 用 `TransactionTemplate.executeWithoutResult`
3. `TransactionTemplate` 通过 `@Resource` 注入（Spring Boot 自动配置提供 Bean）
4. Lambda 内引用 `couponRel` 用 `final OrderCouponRel relToInsert = couponRel` 解决 effectively final

### OrderRequestIdempotencyService

1. 注入 `TransactionTemplate`（`@Resource`）
2. `insertProcessing` → `txTemplate.execute(...)` 独立事务（即使外层回滚仍留痕）
3. `markCompleted` → `txTemplate.executeWithoutResult(...)` 独立事务
4. `markFailed` → `txTemplate.executeWithoutResult(...)` 独立事务

## 行为变化说明

- **旧**：库存扣减失败 → 事务回滚 → 订单不创建（用户看到"库存不足"错误）
- **新**：订单先创建（Phase 3）→ 库存扣减（Phase 4）失败 → 补偿解锁券（Phase 5）→ 异常上抛
  - 用户仍然看到"库存不足"错误（异常传播不变）
  - 区别：订单已落库但会被超时关单（15 分钟）或后续补偿收敛
  - 这是"先建单后扣库存"的 Saga 语义，与 Amazon/阿里订单链路一致
