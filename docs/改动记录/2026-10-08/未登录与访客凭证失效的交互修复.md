# 未登录与访客凭证失效的交互修复（服务端自愈 + 弹窗引导登录）

日期：2026-10-08 ｜ 状态：已修复并上线验证 ｜ 前次记录：[部署前缺陷修复](../2026-10-07/部署前缺陷修复.md)、[线上故障-配置请求风暴](../2026-10-07/线上故障-配置请求风暴.md)

## 需求

用户反馈：线上演示站未登录时使用 AI 客服，只显示「操作未完成（原因码：invalid_visitor）。」——
既没有说明"未登录"，也没告诉用户下一步该做什么。希望改成弹窗提示并引导登录页这类合理的交互。

## 排查

1. **原因码来源**：`assistant/src/smartlect/auth.py` 的 `visitor_id()` 在两个分支抛 `HTTPException(401, 'invalid_visitor')`
   ——访客凭证（`smartlect_visitor` cookie）验签失败或格式不合法时。
2. **为什么会卡住**：`authenticate()` 的访客分支**不去清理失效 cookie**（对比 Java 会话分支有 `delete_cookie`），
   于是密钥轮换、旧格式残留、浏览器里留着的过期 proof 都会让访客**永久**拿不到身份——
   连"逛店 + 问客服"这类访客本就该有的能力也一起没了。本地复现确认：带一个签名错误的 visitor cookie
   提问，稳定复现 401。
3. **前端为什么只显示技术术语**：`web/user/src/api/client.ts` 的 `descriptions` 文案表覆盖了 30 多个原因码，
   但**没有 `invalid_visitor`**，于是走到兜底分支 `操作未完成（原因码：${raw}）`。
4. **401 为什么没有任何提示**：`client.ts` 在 401 时清空会话并派发 `smartlect:identity-changed`，
   但这个事件**只有派发者、没有监听者**——用户停在原地，看不到任何反馈。

## 具体变更

### 1. 服务端自愈（`assistant/src/smartlect/auth.py`）

访客分支改为：失效凭证**清掉并按新访客重新签发**，而不是报错。

```python
visitor = request.cookies.get("smartlect_visitor")
if visitor:
    try:
        identifier = self.visitor_id(visitor)
    except HTTPException:
        visitor = None          # 陈旧 proof 清掉，走新访客签发
if not visitor:
    ...issue_visitor_jwt(...)
```

依据：访客本来就有 `shopping:read`，读路径不该因为一个过期 cookie 把访客挡在门外；
真正需要登录的操作由各自的权限校验去拦（返回 `user_required` / `login_required`）。

### 2. 文案补全（`web/user/src/api/client.ts`）

补 `invalid_visitor`（"访客身份已过期，正在为你重新建立会话。"）、`ambiguous_session_cookie`、
`identity_unavailable` 三条，并让 401 派发的事件**带上原因码**：

```ts
window.dispatchEvent(new CustomEvent('smartlect:identity-changed', {
  detail: { reason: payload.error || payload.detail || payload.info || '' },
}));
```

### 3. 统一引导（`web/user/src/utils/sessionGuard.ts`，新增；`main.ts` 挂载）

按原因分流，避免"一刀切跳登录"：

| 原因码 | 处理 |
|---|---|
| `login_required` / `user_required` / `invalid_session`，以及 401 未带原因码 | 弹窗「请先登录」→ 确认后跳 `/login?redirect=<当前页>`；已在登录页或弹窗未关闭时不重复弹 |
| `invalid_visitor` / `ambiguous_session_cookie` | 静默重建会话（服务端已重新签发），**不**把本来能逛能问的访客赶去登录 |

同时把两处**静默跳转**改为先弹窗说明（用户提的正是"操作没有提示"这一类问题）：

- `components/business/ProductSkuSheet.vue`：未登录点「加入购物车」
- `composables/useProductDetailPage.ts`：未登录点「立即购买」（登录后回 `/checkout`）

`components/business/AddressFormFields.vue` 的未登录提示已有 toast + 跳转，未改动（避免过度改动）。
