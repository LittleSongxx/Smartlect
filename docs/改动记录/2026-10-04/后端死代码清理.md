# 后端死代码清理：Sa-Token 迁移「最后一公里」+ RedisComponent 垃圾抽屉清空

## 需求

体检发现后端存在三类残留：① RedisComponent 451 行中 17 个零生产调用的死方法（多为 RabbitMQ 死信替代前的旧 zset 延迟队列、无消费者的计数器/会员标记）；② Sa-Token 迁移前的死类与孤儿配置（AdminAssertionSigner、admin-assertion.*、admin-interceptor）；③ 网关「只发不收」的身份信任头。全部为行为无关的清理。

## 具体变更

**RedisComponent（451→289 行）**，逐个经全仓 grep 复核零生产调用后删除：
- `getLoginInfo4Admin`（旧管理端内省壳）、`getCategoryList`（读取侧死；`saveCategory2Redis` 有 3 处活调用，保留——当前只写不读，恢复读取需重新设计）
- 旧 zset 延迟队列四件套 `addOrder2DelayQueue/getTimeOutOrder/removeTimeOutOrder/addOrder2DeliverQueue`（已被 RabbitMQ 死信 + Outbox 替代）
- `getUserLocationCoords`（读取侧死，`saveUserLocationCoords` 保留）、`getLogistics(String)`（死方法且带键前缀 bug：读 `...logistics:{sender}` 而写侧不带后缀；`getLogisticsInfo()` 无参版是活的且键一致，保留 save/getLogisticsInfo 对）
- 会员等级领取标记三件（前缀常量 + 读写两方法）、计数器五件套 `incr/decr/getCounter/setCounter/deleteCounter`、`deleteCacheKey`（体检报告漏报，本次复核补获）
- 配套：`SysCategoryServiceImplTest` 删除 `verify(never()).getCategoryList()` 断言行

**死类与孤儿配置**：
- 删 `smartlect-common/.../security/AdminAssertionSigner.java`（HMAC 签名完整实现，零生产引用）+ 其测试
- `smartlect-admin/application.yml` 删 `smartlect.admin-assertion.*` 与 `smartlect.security.admin-interceptor`（消费者已在 ADR-0011 Step 3 删除）
- `smartlect-order/application.yml` 删空 `security:` 节点

**网关信任头**：`AuthGlobalFilter` web/admin 分支不再设置 `X-User-Id`/`X-User-Token-Verified`/`X-Admin-Token-Verified`（经 Java+Python+前端全仓复核零消费者；下游一律 Sa-Token 会话内省自取身份）。保留：无条件剥离客户端伪造身份头、会话键 hasKey/get 校验、401 拒绝。测试同步改断言（`authenticatedRequestStripsSpoofed...`）。ADR-0011 追加 2026-10-04 演进注记。

**小项**：`DateUtil.parse`/`StringTools.checkParam` 的 `e.printStackTrace()` → `@Slf4j` 日志（兜底行为不变）；`DiscountCouponServiceImpl` 顶格缩进修复；order 服务 `V3__baseline.sql` 头部补 V2 断号说明（V2 于 25ef508 随旧表移除，全新部署无影响）。

## 验证

- 回归：`mvn test`（backend 全模块）BUILD SUCCESS，0 Failures / 0 Errors——本次执行通过。
- 真实外部链路（网关在生产不再下发信任头后的联调）：未执行，属部署后验收，标记未知；因零消费者，预期无差异。

## 回滚

单提交 revert；死方法如需找回从父提交 checkout（如未来要做用户位置读取功能，`getUserLocationCoords` 可从历史恢复）。
