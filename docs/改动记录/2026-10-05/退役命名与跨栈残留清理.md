# 退役线命名/话术与跨栈残留清理（P3）

## 需求

推荐/归因线退役（ADR-0008）后的命名与话术残留：`run_shopping(attribution=)` 参数名、`mcp.py`/`adminapi/tools.py` 以已退役的「曝光归因台账」解释工具排除、web 测试 mock 已无人调用的退役端点、Java 侧 `attributionContextToken` 防御剥离（全链路无发送方）与两处 Seata 陈旧注释。

## 具体变更

**Python**
- `session.py`/`app.py`/`test_shopping_mysql.py`：`attribution` → `scenario_scope_store` 单词级改名（含测试 fixture `catalog_attribution`→`catalog_scenario_scope_store`）；错误码 `recommendation_service_unavailable` 不动（模型可见文本、无引用面）。
- `mcp.py`/`adminapi/tools.py`：排除理由改为现行真实语义（会话任务态 + 评测回执；注明归因线已随 ADR-0008 退役）。

**Web**
- `web/user/tests/client.test.ts`：两个用例的载体 URL 从退役端点（`/recommendations/rec1/exposures`、`/traffic/landing`）换成活写端点（`/conversations`、`/preferences/purpose`）；用例本身（超时隔离、CSRF 写前重核验、旧响应不覆盖登录身份）语义不变。
- `web/user/tests/home-promotions.test.ts`：删除 3 个防御性死 mock 分支（exposures/clicks/traffic-landing，src 零调用）。

**Java**
- `OrderCommerceV2Controller.java`：删除 `createConfirmed` 中 `attributionContextToken` 剥离（deepCopy+remove）与 `ObjectNode` import。
- `OrderCommerceV2ControllerTest.java`：原用例拆分——attribution token 畸形值循环删除，保留无关的金额 strict 断言为新用例 `malformedAmountDoesNotCoerceMoney`（3 用例数不变）。
- `CouponRushReconcileTask.java` javadoc、`OrderRequestIdempotencyService.java:69` 注释：Seata 表述改为「已随 ADR-0006 移除，本地事务+Outbox 补偿替代」，保留历史溯源。

**其他**
- `.env.example:44`：「重启 API/worker」的 worker 表述修正（worker 已退役）。
