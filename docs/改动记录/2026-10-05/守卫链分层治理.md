# 守卫链分层治理 ADR-0013（P2，零行为变更）

## 需求

架构评审指出：约 10 个 `looks_like_*` 中文正则意图帧拥有覆盖模型 `request_kind` 声明的改判权，意图识别实为「拆散埋进守卫链的分布式分类器」——是 27 版评测合同锁定的行为（不可盲改），但需要显式分层声明与退役路线。用户决策：本次做**结构化治理**（不改任何判据行为）。

## 具体变更

- 新增 `docs/adr/0013-guard-chain-layering.md`：
  - A 层「证据契约校验」（bind_*/coerce_*/检索预算/no_business_claim_*）——确定性不变量，永久保留；
  - B 层「意图帧启发式」——7 条改判点清单（改判位置 + 效果），声明为待退役层；
  - 降级路线：逐条统计 quality-v2 改判纠错率，不显著为正则降级为提示/审计标记，须过全量 dev + 新 holdout 首测；不设时间表，以模型声明可靠率为唯一判据；
  - 新增守卫准入门槛（B 层原则上不再接受新增）。
- `assistant/src/smartlect/agents/shopping/guardrails.py`：模块 docstring 声明两层与治理路线；A/B 分节注释；每个意图帧函数 docstring 标注改判点与退役判据（`looks_like_product_unique_fact`、`looks_like_service_request`、`looks_like_irreconcilable_sources`、`answer_offers_human_transfer`、`looks_like_catalog_fact_question`）。
- `assistant/src/smartlect/agents/shopping/session.py`：`irreconcilable` 重编点补 `context['irreconcilable_compiled']` 审计旗标（对齐既有的 `exception_frame_compiled`/`handoff_compiled_from_answer`）——仅加 context 键，不改控制流，随 run 快照落库可回放。
- `docs/agent-design.md` 行为守卫小节加分层说明与 ADR 链接。

## 验证

- 零行为变更：全部改动为 docstring/注释/新增 context 键；全量测试绿（非 MySQL 292 + MySQL 63），评测合同不受影响。
- `irreconcilable_compiled` 旗标与既有两个改判旗标同构（审计快照自动携带，见 `decision_record.attach_shopping_audit`）。
