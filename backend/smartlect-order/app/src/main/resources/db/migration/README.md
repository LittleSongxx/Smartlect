# order 服务迁移说明

## 关于 V1 → V3 的版本号跳号

V2 曾在 Phase2 重构（`25ef508`）中随旧表一起移除，编号有意跳过；全新部署按
V1 → V3 顺序执行不受影响。曾应用过 V2 的存量环境需先比对 V2 内容再升级。

## 已应用的迁移文件一个字都不能改

Flyway 对每个迁移文件做 CRC32 校验并与 `flyway_schema_history` 中记录的校验和比对，
**已应用过的 `V*__*.sql` 只要改动一个字节（包括加注释、调换行尾、改编码），
所有先于该次改动应用过此迁移的环境都会在下次启动时直接失败**：

```
Migration checksum mismatch for migration version 3
-> Applied to database : -827808042
-> Resolved locally    : 1806845664
```

2026-10-04 的 `14cbee9` 曾给已应用的 `V3__baseline.sql` 加过两行注释，造成过此类故障；
当时的处置是把注释移出迁移文件（即本文件），让 `V3__baseline.sql` 回到与已应用版本
字节一致的状态，而不是去改数据库里的校验和——后者只修一台机器，前者修所有环境。

因此：

- 说明性文字写在本文件，不要写进已应用的迁移。
- 需要补充 DDL 时新增 `V<n+1>__<描述>.sql`，不要修改既有文件。
- 万一已经改了且无法回退，用 `flyway repair` 更新校验和，但要先确认差异确实不含
  DDL 变更（`git diff <旧提交> <新提交> -- <迁移文件>`），否则会掩盖真实的 schema 漂移。
